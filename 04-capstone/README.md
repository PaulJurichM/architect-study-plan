# Итоговый проект: архитектурный пакет для обезличенной системы

Собрать знания трёх блоков в один артефакт, который можно показать на собеседовании как пример своего архитектурного мышления. Это и проверка, и портфолио.

## Выбор домена

Возьмите знакомую предметную область, но **полностью обезличьте**: никаких названий заказчиков, внутренних систем, реальных схем и цифр. Подойдут, например:

- интернет-магазин с резервированием товара, оплатой и доставкой;
- автоматическое пополнение запасов сети магазинов: прогноз → заказ поставщику → приёмка;
- дистанционное банковское обслуживание юрлиц: платёжное поручение → проверки → исполнение → выписка;
- маркетплейс доменных имён: аукцион → оплата → трансфер.

## Что сделать

Каждый пункт — отдельный раздел в `04-capstone/` (markdown + диаграммы в mermaid или PlantUML).

1. **Контекст и цели** (1 страница): что делает система, ключевые сценарии, 5–7 нефункциональных требований с числами (нагрузка, время ответа, доступность, RPO / RTO).
2. **Доменная модель** ([3.2](../03-microservices-ddd/3.2-strategic-ddd.md)): результаты Event Storming, поддомены с классификацией, ограниченные контексты, карта контекстов с типами отношений.
3. **Решение о декомпозиции** ([3.1](../03-microservices-ddd/3.1-why-microservices.md)): микросервисы, модульный монолит или гибрид — оформить как ADR (Architecture Decision Record): контекст, варианты, решение, последствия.
4. **Схема развёртывания** ([3.3](../03-microservices-ddd/3.3-network-gateway-lb.md)): клиенты, L4 / L7, gateway, BFF, сервисы, брокер, базы. Где терминируется TLS, где проверяется токен.
5. **Интеграции** ([блок 1](../01-http-rest-security/README.md), [3.4](../03-microservices-ddd/3.4-communication.md)): OpenAPI на внешний API (с идемпотентностью, ошибками, пагинацией), AsyncAPI на ключевые события, схема аутентификации и авторизации, чек-лист OWASP API Top 10.
6. **Сквозной процесс** ([3.5](../03-microservices-ddd/3.5-data-patterns.md)): сага с компенсациями, pivot, Outbox, конечный автомат статусов, **таблица отказов**.
7. **Данные** ([блок 2](../02-postgresql/README.md)): модель данных одного сервиса, инварианты и механизмы их защиты (уровень изоляции, блокировки, ограничения), индексы под ключевые запросы, план одной миграции без простоя, требования к репликам и отставанию.
8. **Устойчивость и наблюдаемость** ([3.6](../03-microservices-ddd/3.6-resilience.md), [3.7](../03-microservices-ddd/3.7-observability.md)): таблица политик для внешних вызовов, SLO, бизнес-метрики, алерты.
9. **Риски и открытые вопросы**: что осталось нерешённым и почему.

## Как проверить

- Попросить знакомого архитектора или разработчика провести по пакету ревью в формате собеседования: «почему так, а не иначе?».
- Либо провести ревью с Claude в отдельной сессии: дать пакет и попросить задавать вопросы как интервьюер уровня senior / lead, не подсказывая ответы.
- Каждый вопрос, на который не нашлось хорошего ответа, — повод вернуться к соответствующему модулю.

## Критерий готовности

Пакет можно за 20–30 минут рассказать на собеседовании, и на любой вопрос «почему» есть обоснование с компромиссами.
