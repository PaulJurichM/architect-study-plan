# Этап 0А. Техническая база для перехода из бизнес-анализа

**Для кого.** Для бизнес-аналитика, который переходит в системный анализ, и для системного аналитика уровня junior. Опыт работы с требованиями и процессами есть, а устройство программ, сети, баз данных и интеграций пока знакомо в основном по разговорам с разработчиками.

Этап отвечает на вопрос «как устроено то, что я описываю в требованиях». После него понятны слова, которые говорит разработка: клиент и сервер, HTTP-запрос, JSON, таблица и внешний ключ, SQL, API, очередь, окружение, релиз. И уже можно написать системное требование, по которому разработчик сделает то, что задумано. Глубины здесь нет: только то, без чего не получится читать этап 0Б и основную программу.

## Входной тест

Ответьте вслух на вопросы ниже. Если ответ уверенный и с примером — соответствующий модуль можно пропустить или пробежать глазами: вопросы идут в порядке модулей. Если «плаваете» в трёх и больше вопросах — проходите этап целиком.

1. Что происходит, когда вы открываете в браузере страницу интернет-магазина: какие участники обмениваются данными?
2. Чем отличается ответ 404 от ответа 500 и кто виноват в каждом случае?
3. Как в JSON описать заказ с тремя позициями?
4. Зачем в таблице заказов поле customer_id и что будет, если удалить покупателя?
5. Напишите запрос: сумма продаж по каждому магазину за прошлый месяц.
6. Чем синхронная интеграция отличается от обмена через очередь?
7. Какую диаграмму UML вы нарисуете, чтобы показать порядок вызовов между системами?
8. Что такое тестовый стенд и зачем релиз проходит несколько окружений?
9. Чем user story отличается от системного требования и что такое критерии приёмки?

## Главные источники

- Карл Вигерс, Джой Битти, «Разработка требований к программному обеспечению» (3-е изд.) — основная книга по требованиям.
- Алан Бьюли, «Изучаем SQL» (Learning SQL) — SQL с нуля на практических примерах.
- Мартин Фаулер, «UML. Основы» (UML Distilled) — короткое введение в UML без лишнего.
- Документация MDN Web Docs, разделы «HTTP» и «Web technology for developers» — надёжный справочник по вебу.
- Официальная документация PostgreSQL, глава «Tutorial» — SQL на реальной СУБД.

## Критерий завершения этапа

Для небольшой обезличенной функции (например, «покупатель оформляет заказ с доставкой в интернет-магазине») самостоятельно подготовить мини-постановку: user story с критериями приёмки, диаграмму последовательности вызовов, описание API одного метода в OpenAPI, ER-диаграмму затронутых таблиц и 3–4 SQL-запроса для проверки данных. Показать её знакомому разработчику или системному аналитику: если он может начать работу без уточняющих вопросов про устройство системы — этап пройден.
