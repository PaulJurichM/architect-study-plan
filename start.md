# Как пройти программу самому

Программа открытая: уроки можно читать прямо здесь. Чтобы вести свой прогресс, писать заметки и видеть свою страницу «Прогресс», сделайте собственную копию. Она будет жить в вашем аккаунте GitHub, и ваши отметки и заметки никуда больше не попадут.

Понадобится только аккаунт на GitHub. Устанавливать ничего не нужно, всё делается в браузере.

## Три шага

1. **Создайте копию.** Откройте [оригинальный репозиторий](https://github.com/PaulJurichM/architect-study-plan), нажмите **Use this template → Create a new repository**, придумайте имя (например, `architect-study-plan`) и оставьте видимость **Public**.
2. **Включите сайт.** В своей копии: **Settings → Pages**, в поле Source выберите **Deploy from a branch**, ветку **main** и папку **/ (root)**, нажмите Save.
3. **Создайте issues.** В своей копии: вкладка **Actions** → слева **«Синхронизировать issues»** → **Run workflow**. Через 2–3 минуты:
   - в `_config.yml` появятся адреса вашей копии;
   - появятся milestones по этапам и блокам и по одному issue на каждый модуль.

Сайт откроется по адресу `https://<ваш-логин>.github.io/<имя-репозитория>/`. Первая сборка занимает пару минут. Страница «Прогресс» и плашки в начале модулей будут показывать ваш прогресс.

Если на вкладке Actions GitHub просит подтвердить включение workflows — подтвердите.

## Как отмечать прогресс

- Модуль = issue. Внутри — раздел «Готовность» (на какие модули он опирается) и чек-лист. Отмечайте пункты прямо в issue, страница «Прогресс» подхватит их через пару минут.
- Заметки пишите в раздел «Заметки» в конце модуля: кнопка «Редактировать на GitHub» внизу страницы открывает файл в редакторе. В сообщении коммита напишите `Closes #N` — issue модуля закроется сам.
- Выбирайте, с чего начать, по таблице на [главной](README.md) и по входным тестам этапов 0А и 0Б. Модули, которые вы уже знаете, можно сразу закрыть.

## Шаблон или форк

Копия из шаблона — самостоятельный репозиторий: чистая история, ваши issues. Новые уроки из оригинала сами в неё не приходят.

Если хотите получать обновления, вместо шаблона сделайте **Fork**. Тогда кнопка **Sync fork** будет подтягивать изменения, но в форке придётся вручную включить Issues (**Settings → General → Features → Issues**) и Actions (вкладка Actions). Если вы правили те же файлы, что и автор, при синхронизации будут конфликты. Чтобы их избегать, держите заметки в разделе «Заметки» и не меняйте тексты уроков.

## Приватность

Копия публичная: ваши заметки и отметки видны всем, у кого есть ссылка. Сделать репозиторий приватным можно, но тогда перестанет работать страница «Прогресс»: она читает открытый API GitHub. Кроме того, сайты GitHub Pages для приватных репозиториев доступны только на платных тарифах. Поэтому проще не писать в заметки ничего, что нельзя показывать: названия заказчиков, внутренние схемы, данные с работы.

## Нашли ошибку

Заведите issue или предложите правку (pull request) в [оригинальном репозитории](https://github.com/PaulJurichM/architect-study-plan/issues). Это улучшит программу для всех.
