# Блок 6. Архитектурная практика и документирование

Как архитектор принимает, обосновывает и фиксирует решения: атрибуты качества, ADR, модели C4 и arc42, анализ компромиссов, эволюция архитектуры и работа с легаси. Это то, что отличает архитектора от сильного аналитика: не знание паттернов, а умение выбрать между ними осознанно и оставить след, по которому решение можно понять через год.

## Главные источники

- Mark Richards, Neal Ford, *Fundamentals of Software Architecture* (2nd ed., 2025).
- Neal Ford et al., *Software Architecture: The Hard Parts* (2021).
- Len Bass, Paul Clements, Rick Kazman, *Software Architecture in Practice* (4th ed.) — первоисточник по атрибутам качества и ATAM.
- Neal Ford et al., *Building Evolutionary Architectures* (2nd ed., 2022).
- Simon Brown, *The C4 model for visualising software architecture* и [c4model.com](https://c4model.com); шаблон [arc42.org](https://arc42.org).

## Критерий завершения блока

Для обезличенной системы из своей практики подготовить архитектурный документ по arc42 в сокращённом виде: цели качества со сценариями, диаграммы C4 уровней 1–2, три ADR по ключевым решениям, таблица рисков и технического долга. Этот документ станет частью итогового проекта.
