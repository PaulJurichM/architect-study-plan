# Блок 11. Архитектор как роль: люди, процесс, собеседование

Техническое решение ничего не стоит, если его не приняли люди. Архитектор большую часть времени договаривается: выясняет интересы стейкхолдеров, проводит ревью, оценивает сроки, фасилитирует обсуждения, объясняет компромиссы. Блок — о навыках, которые на собеседовании проверяют поведенческими вопросами, а в работе — каждый день.

## Главные источники

- Gregor Hohpe, *The Software Architect Elevator* (O'Reilly, 2020) — главная книга блока.
- Steve McConnell, *Software Estimation: Demystifying the Black Art* (2006).
- Roger Fisher, William Ury, *Getting to Yes* («Переговоры без поражения»).
- Sam Kaner et al., *Facilitator's Guide to Participatory Decision-Making*.

## Критерий завершения блока

Подготовить банк из 12 историй по методу STAR, покрывающих типовые поведенческие вопросы, и провести два пробных поведенческих интервью. Составить карту стейкхолдеров для текущего проекта (обезличенно) и план работы с ключевыми из них.
